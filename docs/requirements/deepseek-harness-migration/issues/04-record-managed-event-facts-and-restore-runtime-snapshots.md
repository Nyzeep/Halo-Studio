# 04 - 让 Runtime 写入事件事实并恢复安全快照

**待实现内容：** 让 Halo Workbench Runtime 在已规范化的任务生命周期和执行 Adapter 事件进入点写入受管事件事实，并从其恢复安全的任务快照。开发者重启应用后可以重新看到当前任务及其可审查摘要；原本运行中的任务明确变为 `interrupted`，不会恢复外部执行器、重发消息或重放操作。所有写入在进入事实存储前完成统一脱敏和大小限制。

**阻塞于：** 03 - 建立受管事件事实契约与内存 Adapter seam。

**状态：** ready-for-agent

## 实现边界与架构边界

- Runtime 在其现有的深 Module 内、Pi/DSH Adapter 已被翻译为 Halo 状态之后记录事实。原始执行器事件不得越过这个 seam，也不得由前端或存储 Adapter 自行规范化。
- 生命周期、脱敏、大小上限、事实写入失败和恢复不一致的处理集中在 Runtime；Tauri、React、Pi RPC 和存储 Adapter 不拥有第二套状态机。
- 本任务只恢复 Halo 任务快照与结构化摘要。若重启时任何活动任务不能与 Runtime、工作区或外部执行器状态一致，必须投影为 `interrupted`；不得自动恢复会话、重发 prompt/follow-up、重新执行工具或自动作出 Agent 操作决议。
- 事实写入和 UI 投影保持不同职责：UI 继续消费现有 typed snapshot 与有序事件，而不是读取事实存储。证据投影与新鲜度在后续任务实现。

## 验收标准

- [ ] 任务创建、状态迁移、用户/Agent 的安全摘要、工具活动摘要、一次性操作请求/决议、文件变更指纹和任务基线关联，都会生成受控的事实输入。
- [ ] 所有摘要在持久化前经过统一脱敏和大小限制；完整 prompt/response、密钥、原始工具参数/输出、原始 Pi/DSH JSONL 和外部 session log 无法从事实或快照读取。
- [ ] 事实 append 失败有稳定、可观察且 fail-closed 的 Runtime 结果，不会制造未记录却被视为正常推进的状态。
- [ ] 相同事实输入的重复到达符合 03 的幂等契约；任务内的事实顺序与 Runtime 观察顺序一致。
- [ ] 从已保存事实恢复任务快照时，旧 schema 仍可读；此前未结束的任务变为 `interrupted`，而不是运行、完成或等待开发者。
- [ ] 恢复流程不会发起 Pi RPC/DSH 请求、重放工具、写入工作区、恢复一次性决议或自动接受/拒绝交付。

## 验证要求

- 使用内存事实 Adapter 的 Runtime 公开契约测试覆盖写入顺序、重复、脱敏、大小上限、旧 schema 和重启恢复。
- 以可观察的 snapshot 和 intent 结果验证不重放，而不是 mock Runtime 内部协作者或检查私有状态。
- 运行受影响的 Rust contract/runtime/desktop 测试、最小类型检查或边界检查，以及 `git diff --check`。

## 不在本票

- 冻结交付证据、工作区变化导致 `stale`、证据删除或 UI 的证据细节投影。
- 真实 Pi/DSH 执行、真实数据库/文件持久化格式的兼容验收；若尚未实际运行，保持 `not-run`。
