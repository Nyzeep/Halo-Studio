# 05 - 投影交付证据、新鲜度与 typed UI 状态

**待实现内容：** 从 Halo 事件事实、任务基线和工作区指纹生成独立且可冻结的交付证据快照，并将其新鲜度与审查状态通过 Halo Workbench Runtime 的 typed projection 提供给 UI。开发者可以在重启后重新打开审查，看到覆盖范围、验证摘要和过期状态；覆盖文件后来变化会使证据 `stale`，且无论回放还是投影都不能自动接受或拒绝交付。

**阻塞于：** 04 - 让 Runtime 写入事件事实并恢复安全快照。

**状态：** ready-for-agent

## 实现边界与架构边界

- 交付证据是独立的派生快照，不是事件事实日志、瞬时 UI event 或外部执行器 session。投影 Module 负责把事实、任务基线和工作区指纹组合为冻结版本，并收口覆盖范围与新鲜度规则。
- 文件变化只会使受影响证据失效；它不会修改原事实、自动重新执行任务、自动生成新证据或替开发者接受/拒绝。
- Renderer 仅经 Workbench Runtime 的既有 typed snapshot、intent 和有序 projection 读取审查状态。它不直读事实存储、Git 基线实现、Pi/DSH 日志或原始外部标识。
- 证据存储、保留和用户删除遵循统一脱敏、大小上限和本地历史策略；删除后投影不能留下可恢复的敏感证据内容。

## 验收标准

- [ ] 受管任务完成审查准备时，可从事件事实、任务基线和工作区指纹派生并冻结一个有版本的交付证据快照。
- [ ] 快照记录覆盖范围、覆盖文件、验证摘要、基线关联和新鲜度，且不包含完整模型内容、凭据、原始工具参数/输出、原始 Pi/DSH JSONL 或外部 session log。
- [ ] 任一覆盖文件后续发生变化时，相关快照明确成为 `stale`；原快照仍可查看，但不得在未重新审查的情况下接受。
- [ ] 应用重启后可以重新打开审查页；事实、工作区或外部执行器不一致时，证据和任务分别投影为 `stale` 或 `interrupted`，不会自动恢复执行。
- [ ] 只有本地开发者的明确 accept/reject intent 能改变交付结论。重放、快照恢复、事实追加或证据投影都不能替代该人工决议。
- [ ] UI 的 typed projection 展示可审查状态而不扩大 Runtime Interface 为原始日志/事实数据库浏览器。
- [ ] 用户删除本地历史后，事实和证据的可见投影同步删除，并继续满足脱敏与大小上限规则。

## 验证要求

- 通过 Runtime 公共 Interface 验证快照冻结、文件变化后的 `stale`、重启审查恢复和人工决议不可由回放替代。
- 使用基线、工作区指纹和事实的已知输入断言证据行为，避免把事件日志对象本身当成交付证据。
- 运行 Runtime/desktop/Web typed-projection 的 focused tests、相关类型检查、仓库边界检查和 `git diff --check`。

## 不在本票

- 真实 DSH 持久化/replay、真实 Pi 会话验收或任何真实模型调用；未实际执行时一律标为 `not-run`。
- 自动接受、自动拒绝、自动重放、自动恢复执行器，或新增生产执行 Adapter。
