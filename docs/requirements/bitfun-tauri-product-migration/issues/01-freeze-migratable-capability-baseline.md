# 01 - 固化可迁移能力基线与仓库卫生

**What to build:** 维护者可以从一份可重复的自动化结果和状态记录确认旧六票中哪些行为已成为可迁移能力基线、哪些真实验收仍未完成，并在不删除旧产品实现的前提下清除可确认的临时产物。

**Blocked by:** None - can start immediately.

**Status:** ready-for-agent

- [ ] 在 MSVC 开发环境中记录 workspace 检查、构建、Rust 测试、Python/QML 验证和 Schema 验证的精确命令与结果。
- [ ] 将旧六票明确标为“可迁移能力基线”，不得表述为目标 Tauri 产品已验收或 P0 已放行。
- [ ] 将真实 OpenCode 原生 UI 验收保持为未完成门槛，并保留此前失败的归类与复现证据。
- [ ] 只移除可确认的临时测试目录、缓存和安装器；用户改动、迁移文档、旧 QML/Sidecar 源码和外部上游参考树不得被误删。
- [ ] 基线代码、测试与状态文档形成可独立审查的提交边界，不混入迁移实现或无关工作树改动。
