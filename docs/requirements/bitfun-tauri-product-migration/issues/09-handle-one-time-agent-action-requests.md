# 09 - 映射 OpenCode 一次性操作请求

**What to build:** 当 OpenCode 受管 Session 发出 permission 或 question 请求时，本地开发者可以在 Halo 原生 UI 对准确的当前请求作出一次性决定；Halo 只在 OpenCode 原生确认对应决议后继续任务。

**Blocked by:** 08 - 完成首轮 OpenCode 受管任务会话.

**Status:** ready-for-agent

## 验收标准

- [ ] Adapter 将 `permission.asked` 与 `question.asked` 规范化为带 Halo 本地关联标识的 Agent 操作请求，并隐藏 OpenCode 原始请求、Session 和认证标识。
- [ ] 权限请求只能“本次允许”或“拒绝”；不得投影 OpenCode 可能存在的永久、会话级或全局放行选项。
- [ ] 澄清请求只能回答或拒绝；答案只在一次原生 reply 调用期间存在，不进入日志、证据或完整历史。
- [ ] 浏览器或 Computer Use 对工作区外产生写入、提交、上传、下载、剪贴板写入、进程或系统控制影响时，必须规范化为高风险外部操作请求。
- [ ] 请求在决议提交期间不可重复响应；过期、错任务、错种类或重复决议失败关闭，不得批准另一请求。
- [ ] UI 请求只在 OpenCode 的匹配 replied/rejected 事件确认后消失；HTTP 成功但无原生确认不能伪造已解决。
- [ ] 应用关闭、任务取消或事件流断开时，所有待决请求按事实收口，不在重启后自动重放或自动批准。

## 验证要求

- 自动化覆盖允许、拒绝、回答、过期、重复、错关联、原生失败、迟到确认、取消竞态和重启不重放。
- 脱敏测试使用包含伪 Authorization、路径、远程标识和答案的载荷，断言公开 Interface 与持久化均不泄漏。
- 前端只能呈现 P0 支持的一次性控件，不显示“始终允许”或通用批准对话框。

## 不在本票

- 不修改 OpenCode 全局权限配置，不建立 Halo 永久授权规则。
- 不自动替用户批准任何工作区外写入。
