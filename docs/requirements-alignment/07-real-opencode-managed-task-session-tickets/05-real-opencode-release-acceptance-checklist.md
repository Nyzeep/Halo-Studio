# #14 真实 OpenCode 发布验收清单

**用途：** 在可丢弃的验收工作区中，由开发者通过 Halo Studio 原生界面验证真实 OpenCode 受管会话闭环。

**当前状态：** 自动化证据已补齐；本模板中的真实凭据、验收工作区和原生 UI 步骤尚未执行，不得将未勾选项报告为通过。

## 前置条件

- [ ] 使用专门的、可删除的 Git 验收工作区；不得使用产品仓库或包含无关工作的工作区。
- [ ] 工作区已初始化 Git，且已确认工作区信任；验收前后记录 `HEAD` 和工作树状态。
- [ ] Halo Studio 通过系统凭据存储中的凭据引用启动 OpenCode；记录中不写入密钥、凭据明文或完整引用内容。
- [ ] 选择本地安装的 OpenCode 1.x 可执行文件和受支持的 `provider/model` 配置。
- [ ] 确认本次运行不是 CI、测试替身或在线模型自动化；真实模型调用只由开发者在本清单下明确触发。

## 原生 UI 验收步骤

### 1. 启动与兼容性

- [ ] 在原生配置界面选择 OpenCode、模型和凭据引用。
- [ ] 启动受管运行时，确认界面显示真实 OpenCode 已就绪。
- [ ] 记录 OpenCode 版本和 `opencode-server-1.x` 兼容性档案结果；不记录端口、Basic Authorization、session/message id 或密钥。
- [ ] 对不兼容版本、缺失凭据或健康检查失败，确认界面显示失败原因和恢复建议，而不是显示为可用。

### 2. 首轮真实会话

- [ ] 创建受管任务，发送一条明确且最小的首轮消息。
- [ ] 确认界面显示用户消息和整理后的 Agent 回复。
- [ ] 确认首轮回复后任务处于“等待开发者”，没有自动进入交付完成或审查状态。

### 3. 一次性操作请求

- [ ] 让 Agent 触发一次权限或澄清请求。
- [ ] 通过界面只处理本次请求：允许一次、拒绝，或提交一个非空澄清回答。
- [ ] 确认不存在“始终允许”或跨任务授权；请求必须在对应的原生反馈后消失。

### 4. 追问与同一任务连续性

- [ ] 等待任务再次进入“等待开发者”。
- [ ] 在同一任务中发送一条追问，确认收到第二轮整理后的回复。
- [ ] 确认追问不能在运行中重复提交，也不能创建第二个任务或新的公开会话记录。

### 5. 无害工作区改动

- [ ] 要求 Agent 在验收工作区创建或修改一个无害标记文件，例如 `halo-acceptance-marker.txt`。
- [ ] 在工作区和审查界面确认文件确实存在，Diff、摘要和验证结论与事实一致。
- [ ] 确认 Halo Studio 没有自动提交、回滚、删除文件、改写历史或改变开发者原有改动。

### 6. 显式结束与审查

- [ ] 在开发者确认交流足够后显式结束会话。
- [ ] 确认会话文本和原始工具输出被清除，不进入标准历史或交付证据。
- [ ] 打开只读审查，核对关联 Diff、摘要、归因和验证结论。
- [ ] 在审查结果确认前，不报告任务已接受；accept/reject 只记录本地结论并保持 Git 不变。

## 中断与不重放核对

自动化测试必须先通过；真实验收时可以在独立验收工作区额外观察下列事实：

- [ ] 任务运行中关闭应用或 Sidecar 后，重启只显示 `interrupted`，没有自动恢复当前任务。
- [ ] 没有自动重连远端 session、重发消息、重放操作请求或重复 Agent 写入。
- [ ] 中断前已有的工作区文件和已生成的审查证据仍按事实保留。

## 兼容性档案变更门槛

- 新增或扩大 OpenCode 1.x 兼容范围时，必须同时提交对应协议能力的自动化证据：健康检查、认证、session、message、事件流、一次性请求、追问和停止清理。
- 同一范围必须补充一次真实原生 UI 验收记录；只有模板未填写或只运行假服务时，不得声称该版本范围已发布验收。
- OpenCode 2.x 不自动继承 `opencode-server-1.x` 档案。必须建立独立档案、协议证据和真实验收记录后才可单独放行。
