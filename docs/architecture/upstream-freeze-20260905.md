# 上游快照冻结只读（2026-09-05）

> 状态：生效中（工单：#50；决策地图：#32）
> 守卫：仓库卫生检查 `product/Halo Studio/scripts/check-repo-hygiene.mjs` 在冻结路径出现未提交改动时直接失败
> 解除方式：整体删除，不逐项解冻

## 冻结范围

- `product/Halo Studio/vendor/`：cargo 上游依赖树（约 5.8 万个跟踪文件）。
- `product/Halo Studio/halo-scope.json`：ADR-0067 装配范围机制。
- `product/Halo Studio/MiniApp/`：上游来历的范围外模块（halo-scope `excludedModules` 已排除）。
- `BitFun-latest/`（仓库根）：已 gitignore 的上游参考快照，保持未跟踪状态，不进入版本库。

## 冻结原因

「去 BitFun 化」重构（#32）采用行为等价迁移：迁移期间需要稳定的上游快照作为行为对照物，上游树一旦继续漂移，等价性验证就失去参照。当前仓库是 ADR-0066 定义的受控下游（只拉取 `GCWing/BitFun.git`），产品树内按 ADR-0067 保留完整上游源码关系；冻结不改变这一结构，只是停止对其中上游来历部分的增量修改，直到迁移完成。

## 解除条件

新基座的第一个真实验收版本通过后，`vendor/`、上游来历树与 `halo-scope.json` 作为独立、可审查的最终变更整体删除。这与 ADR-0054「仅在经验证迁移后删除旧源码」一致：不在迁移开始或仅能启动后提前删除，也不做渐进拆改；与 ADR-0026 同源：旧资产在显式、可验证的迁移完成前保持原样，不做静默改写。

## 守卫语义

仓库卫生检查对冻结路径的任何未提交改动（修改、暂存、删除、未跟踪新文件）报告失败；`BitFun-latest/` 一旦被跟踪（含暂存）同样失败。守卫是工程提醒而非权限系统：绕过它等于绕过行为等价迁移的对照前提。
