# 冻结上游源码树只读并在 2.0 验收后整体删除

## ADR 关系

- Supersede(s): ADR-0051、ADR-0066、ADR-0067。「一次性导入上游源码树」「受控上下游同步」「完整上游树 + halo-scope 装配范围」三条机制随「去 BitFun 化」重构停止运行：冻结期间不再有上游同步候选与装配范围变更；新基座 Rust 侧只保留 Halo 自有 crates，BitFun 上游依赖清零。
- ADR-0068 保留：产品源码继续位于 `product/` 树，布局不变。ADR-0054「仅在经验证迁移后删除旧源码」与 ADR-0026「旧资产保持原样、不静默改写」的原则由本 ADR 具体化为「冻结 → 新基座真实验收 → 整体删除」路径；MIT 归属义务（ADR-0052）在删除后继续满足。

## 决策

（决策地图 #32）

- **冻结范围**（#50）：`product/Halo Studio/vendor/`（cargo 上游依赖树）、`product/Halo Studio/halo-scope.json`（ADR-0067 装配范围机制）、`product/Halo Studio/MiniApp/`（上游来历的范围外模块）、根 `BitFun-latest/`（已 gitignore 的参考快照，保持未跟踪）。
- **守卫机制**（#50）：仓库卫生检查 `product/Halo Studio/scripts/check-repo-hygiene.mjs` 对冻结路径的任何未提交改动——修改、暂存、删除、未跟踪新文件——直接失败；`BitFun-latest/` 一旦被跟踪（含暂存）同样失败。守卫是工程提醒而非权限系统：绕过它等于绕过行为等价迁移的对照前提。
- **冻结原因**：2.0 重构采用行为等价迁移，需要稳定的上游快照作为行为对照物；上游树一旦继续漂移，等价性验证就失去参照。
- **迁移基线先封版**（#48）：旧验收链（旧六票验收记录、Runtime/PiRpcAdapter/Web 契约证据）已封版为 tag `migration-baseline-20260905`；未完成的旧 P0 发布目标（真实 UI 主链、release gate）如实标记为「由 2.0 重构取代」，重构不背旧 P0 发布目标。
- **解除条件**：新基座的第一个真实验收版本通过后，`vendor/`、上游来历树与 `halo-scope.json` 作为独立、可审查的最终变更**整体删除**——不逐项解冻、不做渐进拆改，与 ADR-0054/0026 一致。删除完成后，ADR-0066 定义的上游同步流程不再运行，上游能力不再进入 2.0 基座。

## 后果

- 仓库进入「上游只读对照 + Halo 自有基座并行」状态：冻结路径之外的开发照常进行，任何触及冻结路径的变更都会在卫生检查处被拦截。
- 依赖 vendor 树或 halo-scope 装配的旧构建路径在冻结期保持可复现基线，但不再接受为 2.0 新能力的落点；新基座能力一律落在 Halo 自有 crates。
- MiniApp 的最终去留是独立雾区事项，不因本冻结预设立场（见 2.0 重构规格「显式延后」）；冻结本身不等于删除决定。
