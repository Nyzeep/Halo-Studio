# 采用 niri 条带空间模型作为工作台 UI 架构

## ADR 关系

- Supersede(s): ADR-0027、ADR-0018。ADR-0027 的「高密度三栏工作台」空间模型被条带范式替换；ADR-0018 的约束对象（保留上游 BitFun 工作台交互骨架）随「去 BitFun 化」重构消失，其稳定位置、高密度、可反复对照任务状态与结果的价值诉求由条带模型继承。
- ADR-0028（任务列表按工作区）与 ADR-0029（会话历史按工作区隔离）保留，由「每工作区一条带」直接承载；ADR-0030 保留并演进，其入口从工具栏/上下文菜单改为 Spotlight 式命令面板；ADR-0050 的交付证据、新鲜度与 typed UI 状态语义不变。
- niri（GPL-3.0）只作为交互范式来源：不复制其代码或资产，条带、Overview 与手势的实现全部原创；只借鉴交互范式与行为语义，MIT 归属不受影响（ADR-0052）。

## 决策

（决策地图 #32）Halo Studio 2.0 工作台整体重写为 niri「可滚动条带 + 列」空间模型的转译（#43 原型、#44 决议）：

- **条带空间模型三要素**：
  - **工作区轨**：Git 工作区的常驻切换轨；每工作区拥有独立任务条带（对应 niri「每显示器独立条带」），条带互不溢出，承载 ADR-0028/0029 的按工作区隔离。
  - **任务条带**：受管任务按列排在向右延伸的条带上；新建任务在焦点右侧插入，**不挤压、不重排既有列**（与 i3/sway 式平铺的本质差异）。进行中任务的视觉位置保持稳定，与交付证据审查所需的位置连续性一致；「永远可以新建任务」是条带右向开放的视觉承诺。
  - **Overview**：全部条带缩小縮远的导航层，按工作区分组，以状态色 + 标题截断呈现任务；极端列数下分页（P0 要求）。
- **六表面清单**（#44）：
  1. **工作台**（主表面）= 工作区轨 + 任务条带 + Overview。
  2. **任务列**（列内）：会话流（活动会话记录）+ 工具活动 chips + Agent 操作请求卡内联在会话流中（两执行器决议统一渲染，见 ADR-0078）+ 交付审查区（证据快照、新鲜度、接受/拒绝，ADR-0047/0050 语义不变）。
  3. **命令面板**（Spotlight 式）：ADR-0030 会话内命令的入口演进 + 任务创建 + 工作区跳转 + 执行器选择（仅任务创建处，见 ADR-0078）。
  4. **Git 面板**：ADR-0055–0063 全套用户驱动语义保留，作为每工作区可开合表面，不做全屏。
  5. **设置**（分区式）：模型/凭据（ADR-0064）、执行器默认、诊断导出（ADR-0042–0044）、主题。
  6. **标准编码模式**：与受管模式在工作区轨分层呈现（ADR-0016 保留）。
- **手势与输入 P0 集**（#45，含对 #43 原型的一处修正）：
  - 触摸板双指横滚 = 条带横移（原生 overflow 语义）；**滚轮 = 只滚列内，不链横移**；Shift+滚轮 = 条带横移。
  - 键盘全集：←→ 焦点列、`n` 新建任务（焦点右侧插入并跳转焦点）、`o` Overview、`1..9` 工作区跳转、Esc 退层。
  - Overview：状态色 + 标题截断 + 按工作区分组 + 极端列数分页。
  - 捏合 → Overview 为 P1；动效全局尊重 prefers-reduced-motion（动效 token 见 ADR-0077）。
  - 无障碍底线：全部手势都有等价键盘路径（#43 原型原则延续）。

## 后果

- 三栏工作台的既有实现与交互断言不迁移；「打开新任务不重排既有列」成为列内状态与测试的新约束，任务列内的会话流、工具活动与证据纵向增长而不横向挤压。
- niri 原语只在有明确 Halo 对应物时转译（列内堆叠、tabs 分组、手势）；compositor 专属能力（screencast、xwayland 等）不转译。
- 条带 shell 的实现依赖 ADR-0077 的 token 层、双 store 与本 ADR 的表面清单、手势集；长任务列表条带 UI 的虚拟化性能预算显式延后（见 2.0 重构规格「显式延后」）。
