# 受管执行器统一事件泵按 kind 分区过渡，端口保持执行器中立

## ADR 关系

- 落实 ADR-0078 的统一端口接缝：把「Runtime 消费统一执行器事件」从契约条文推进为真实事实路径，同时把过渡期的接缝所有权边界固定下来，避免在 M6（#58）验收前做不可逆的事实身份迁移。
- 遵守 ADR-0080「不虚构历史」与单一脱敏闸门：统一泵投影与传输路径共用同一事实 kind 词汇与同一闸门，不另立事实层。

## 决策

（决策地图 #32；#60）

- **统一事件泵按执行器 kind 分区过渡**：Runtime 为每个已安装受管执行器维护幂等的统一事件泵；Pi RPC 的事实继续由传输事件泵独占（其拥有 Pi 方言 generation 模型），其余执行器（今天即 DSH）经 `project_managed_executor_event` 单一投影落托管事实账。未知会话与已过期 generation 的事件丢弃不记录。
- **generation 不跨统一端口**：`ManagedExecutorPort` 及其事件词汇保持执行器中立，不携带 Workbench adapter generation。统一事件以「当前 generation 会话存在性」做等价门控，门控语义写入接缝契约文档，不以携带 Halo 内部标识为代价换取显式性。
- **事实身份空间按执行器分区**：Pi 传输路径保留 Halo 局部身份种子（如 `{call_id}:started`），统一投影使用端口身份种子（`task_id ␁ session_id ␁ call_id ␁ phase`）。不做存量身份迁移；幂等性以「同一执行器同一事件同一身份」在每个分区内保证。事实账消费者不得假设全局统一身份格式。
- **活动帧不经统一端口**：流式文本等 live 活动仍由传输事件路径驱动「活动会话记录」，Runtime 摄入侧脱敏（`redact_halo_text`）保持不变；活动路径的统一化待 P1 活动记录契约再议（#60 决议 3）。
- **执行面意图原生**：受管会话的 prompt / follow-up / abort 由 Halo 意图直达绑定端口（`SessionAdapterAction`），不再构造 `PiRpcCommand` 翻译垫片；会话创建、拆除与决议登记暂留传输路径，如实记录为 ② 剩余项。
- **`PiRpcPortExecutorBridge` 保留**：它是注入 `PiRpcPort` 的受管视图，删除前置是把默认构造器与契约测试夹具改为显式安装端口实现（构造器重设计），随会话生命周期决议一并收敛。

## 后果

- 统一端口契约保持 9 方法 + 事实词汇不扩面；第三个受管执行器接入只需实现端口并安装，事实路径自动生效。
- DSH 受管会话的事实（用户消息、工具活动、回复、决议、中断、失败尝试）自本 ADR 起经统一泵真实落账；M6（#58）真实 DSH 主链验收具备事实面。
- 两条事实路径 kind 一致但身份格式不同：重建、幂等与审计逻辑按执行器分区处理；跨分区合并身份是禁止操作。
- CreateSession/EndSession/ResolveOperation 对非 Pi 执行器的传输登记是已知过渡泄漏，随会话生命周期跨端口决议（#60 决议 1 的后续）收敛；在此之前不得为非 Pi 执行器新增依赖传输会话状态的功能。
