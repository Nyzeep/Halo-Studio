# 06 - 真实 OpenCode 受管任务会话规格

**状态：** 待开发票据确认  
**来源：** `04-real-opencode-managed-task-session.md` 与 `05-real-opencode-managed-task-session-wayfinder.md`  
**发布目标：** Halo Studio 首个真实 Agent 应用能力闭环

## Problem Statement

Halo Studio 当前能以测试替身证明任务、审查和安全边界，却无法证明本地开发者能在原生界面启动真实 OpenCode、与其交流并完成一个简单任务。现有 OpenCode 适配器仍依赖过时的假设协议，任务会在一轮运行后终止，界面也没有可继续的会话记录。

本地开发者需要一个受控、可审查且不泄漏凭据的方式，在受信任的 Git 工作区中完成真实 Agent 任务，而不是获得一个通用聊天工具或一个仅在测试中可用的模拟界面。

## Solution

Halo Studio 将提供以任务为单位的受管 OpenCode 会话。开发者显式配置 OpenCode、模型和凭据引用，在验收工作区启动经过兼容性档案检查的 OpenCode 1.x 服务，发送任务消息并接收整理后的回复。一次回复后任务进入“等待开发者”，开发者可继续追问、一次性处理操作请求，或显式结束会话并进入既有只读交付审查。

该方案以版本化 IPC 为唯一界面边界。OpenCode 的真实会话、消息、事件和权限协议仅由 Rust Sidecar 适配；Python/QML 只消费受控的任务状态、会话消息、操作请求和审查数据。完整对话、原始工具日志和凭据不持久化。

## User Stories

1. 作为本地开发者，我想显式选择一个验收工作区，以便在不影响实际项目的情况下验证真实 Agent 能力。
2. 作为本地开发者，我想在界面中选择 OpenCode 程序、模型和凭据引用，以便清楚知道本次任务使用什么运行环境。
3. 作为本地开发者，我想在启动前看到 OpenCode 是否通过兼容性检查，以便不在不支持的版本上开始任务。
4. 作为本地开发者，我想看到版本不兼容、凭据缺失或服务无法启动的具体原因和恢复建议，以便自行修复配置。
5. 作为本地开发者，我想显式创建一个 Agent 任务并输入第一条任务消息，以便控制 Agent 的工作目标。
6. 作为本地开发者，我想看到自己的消息和 Agent 的文本回复，以便判断是否需要继续追问。
7. 作为本地开发者，我想在同一任务中继续发送追问，以便基于 Agent 已完成的工作澄清或修正方向。
8. 作为本地开发者，我想在 Agent 一轮回复后看到“等待开发者”，以便知道任务尚未自动结束。
9. 作为本地开发者，我想在 Agent 请求权限时只批准本次操作，以便完成任务而不留下永久放行规则。
10. 作为本地开发者，我想拒绝权限或回答澄清问题，以便保持对任务行为的控制。
11. 作为本地开发者，我想在 Agent 工作期间看到规范化运行轨迹，以便了解进度而不阅读原始终端日志。
12. 作为本地开发者，我想显式结束会话并进入审查，以便在我认为交流足够后固定交付结果。
13. 作为本地开发者，我想看到任务基线之后的文件 Diff、摘要和验证结论，以便决定接受或拒绝交付。
14. 作为本地开发者，我想确认接受或拒绝不会自动修改 Git 历史或删除文件，以便保留我的工作区控制权。
15. 作为本地开发者，我想在应用意外退出后看到任务被如实标为中断，以便避免重复执行未知操作。
16. 作为本地开发者，我想让会话文本在结束后不进入完整历史，以便避免保存不必要的敏感内容。
17. 作为本地开发者，我想在 OpenCode 1.x 更新后继续使用 Halo Studio，只要所需协议能力仍然通过检查。
18. 作为本地开发者，我想通过原生界面完成一次真实验收，以便确认产品能力不是由测试替身伪造的。

## Implementation Decisions

1. **任务仍是唯一会话容器。** 外部 API 不新增通用聊天资源；任务创建的 `instructions` 作为第一条用户消息，后续消息只能发送给同一活动任务。
2. **任务状态机追加“等待开发者”。** P0 的核心路径为 `created -> running -> waiting_developer <-> running -> finishing -> review_ready`。权限或澄清将任务置为 `awaiting_action`；取消、失败和中断保持既有终态语义。
3. **会话动作采用任务命名空间。** 在既有任务契约上追加发送消息和结束会话动作；发送消息仅在 `waiting_developer` 可用，结束动作仅在安全的轮次边界可用。空消息、错误状态和未知任务必须失败关闭并给出稳定错误码。
4. **会话消息是追加式 IPC 事件。** 事件至少包含任务标识、角色、经脱敏限长处理的文本和截断标记。活动任务快照必须能重建当前活动会话记录；任务结束后该记录不写入交付历史。
5. **OpenCode 使用真实会话协议。** Sidecar 负责以回环服务、每次启动认证和 Basic 认证连接 OpenCode，建立任务对应的 OpenCode session，发送初始消息与后续消息，消费服务器事件流，并将内部会话标识、端口和认证信息保持私有。
6. **一次回复不产生交付终态。** Sidecar 在 OpenCode 完成一轮消息后规范化出回复和“等待开发者”；只有开发者显式结束会话才触发结束树、证据和审查流程。
7. **兼容性档案取代精确版本锁。** P0 支持不低于 1.18.5 的 OpenCode 1.x，前提是匹配已知兼容性档案。档案定义安全启动、认证、健康、会话、消息、事件、操作请求和结束所需的能力。未知主版本不启动，未知或缺失能力不伪造可用。
8. **兼容性检查分阶段进行。** 启动阶段验证版本家族、认证和健康能力；创建真实会话时验证 session、消息和事件能力。任一失败都使本次运行不可用或任务失败，并带恢复建议。
9. **凭据仍由受管启动配置提供。** 配置只保存凭据引用和模型中的受控 Provider 选择；Sidecar 由该选择通过内置白名单映射确定凭据环境变量，配置、UI 和 IPC 不接受任意变量名。密钥只在 Sidecar 启动受管进程时从 Windows 凭据管理器短暂读取并注入受限子进程环境。
10. **活动会话记录和运行轨迹分离。** 活动会话记录只展示用户消息与 Agent 文本回复；运行轨迹只展示规范化阶段、文件提示、生命周期和操作请求。二者均不显示原始工具输出。
11. **操作请求必须由开发者一次性决议。** 现有操作请求契约扩展为完整回路：权限可本次允许或拒绝，澄清可回答或拒绝；不实现“始终允许”。
12. **最小界面改造基于现有任务表面。** P0 在现有任务、轨迹、配置和审查表面上增加会话记录、消息输入、发送、结束会话和操作请求卡片；不等待 IDE 壳层或编辑器实现。
13. **显式结束才生成审查证据。** 结束会话后沿用现有临时索引 Git 基线和只读审查机制生成关联 Diff、摘要与验证结论；接受/拒绝不触发 Git 写操作。
14. **中断不自动恢复。** Sidecar 或应用重启后将未结束任务标记为中断，清除内存中的活动会话记录和远程会话句柄，不重发任何消息。
15. **14 号设计的 P0 修订是追加式的。** 真实 OpenCode 协议、认证和事件原则继续采用 14 号设计；其单轮终态、严格版本相等和运行时事件封闭集合不再满足 P0，需要追加多轮会话和兼容性档案能力。

## Testing Decisions

1. **主要测试接缝是版本化 IPC。** 好的测试验证界面可观察的状态、消息、请求和审查结果，不断言 QML 或适配器的私有实现细节。
2. **界面测试使用测试 Sidecar。** 覆盖创建任务、消息追加、等待开发者、发送追问、结束会话、操作请求卡片、错误呈现和活动会话记录清空，不让 UI 直接依赖 OpenCode。
3. **Sidecar 集成测试使用讲真实协议的测试 OpenCode。** 覆盖兼容性档案、Basic 认证、会话创建、初始与后续消息、事件流、权限或澄清回复、显式结束、取消和中断。
4. **运行时单元测试覆盖协议适配。** 覆盖版本解析、能力缺失、认证失败、事件乱序或断流、消息脱敏截断、未知事件前向兼容和不泄漏认证信息。
5. **状态机测试覆盖所有可见迁移。** 特别覆盖 `waiting_developer` 不是终态、仅允许在正确状态发送或结束、拒绝权限、错误、取消和重启中断。
6. **持久化与安全测试覆盖负面行为。** 断言完整会话文本不进入历史或证据；凭据、端口和认证密码不出现在 IPC、日志、错误或数据库；接受/拒绝不改变 Git。
7. **真实会话验收是发布门槛。** 在验收工作区通过原生界面运行真实 OpenCode，完成一次文件改动、一次追问、一次显式结束和一次审查。该验收为人工明确触发，不进入持续集成。
8. **版本升级回归受兼容性档案约束。** 每个新增的 OpenCode 1.x 兼容范围都必须新增对应协议测试和真实会话验收记录；2.x 必须先建立新档案。

## Out of Scope

- Pi 真实运行、Pi 多轮会话和 Pi 协议升级。
- 无限自由聊天、跨任务会话、多会话并发、会话云同步和完整会话档案。
- 自动恢复、自动重试、自动故障转移、自动委派和自动批准权限。
- IDE 壳层、编辑器、资源管理器、文件系统写入、命令面板和 15 号差异化功能。
- 自动 Git 提交、分支、推送、发布、回滚或删除工作区文件。
- 在持续集成中使用真实模型凭据或实际在线模型调用。

## Further Notes

- P0 的“简单任务”必须包含真实 Agent 产生的工作区改动；纯文本回答不足以证明初步应用能力。
- 任务说明仍只携带开发者显式提供的内容，不能因会话能力而自动附带整个工作区、历史或打开文件。
- 任何未来 IDE 功能若消费任务会话信息，必须遵守本规格的脱敏、显式上下文和只读审查边界。
- 已确认的纵向实施拆分见 `07-real-opencode-managed-task-session-tickets/`。
