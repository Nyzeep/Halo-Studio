# 04 - 确定交互、安全与质量边界

**类型：** grilling  
**状态：** resolved  
**Blocked by：** 01 - 定义受管任务会话边界, 03 - 确定 P0 发布范围与真实验收场景

## Question

用户如何看见和处理真实会话，权限或澄清怎样处理，意外中断怎样处理，以及怎样避免各层单测通过但整体失败？

## Answer

任务界面增加活动会话记录：显示用户消息和经脱敏、限长整理后的 Agent 回复；原始工具日志只作为规范化运行轨迹，不进入会话记录或历史。

权限和澄清请求以内嵌卡片处理，只支持本次允许、拒绝或填写回答，不提供永久规则或自动批准。

应用或 Sidecar 意外退出时，未结束任务标为中断，不自动重连、恢复或重放。版本化 IPC 是唯一主要测试边界：界面只经 IPC 交互，自动化用测试 Sidecar 和测试 OpenCode 覆盖完整路径，真实 OpenCode 由人工验收确认。

## Consequences

- 会话、权限、结束和审查必须是同一条纵向路径。
- 测试和生产都不得出现 UI 直连 OpenCode 的旁路。
- 中断后的任何后续行为都必须由开发者显式发起。
