# 02 - 确定真实运行时、兼容性与凭据边界

**类型：** grilling  
**状态：** resolved  
**Blocked by：** None

## Question

首个真实闭环使用哪个受管应用，如何处理 OpenCode 更新，以及如何安全地让它获得模型凭据？

## Answer

OpenCode 是 P0 唯一的真实端到端发布门槛。本机已验证存在 OpenCode 1.18.5；Pi 未安装，因此 Pi 真实运行不阻塞 P0。

OpenCode 支持从 1.18.5 开始的 1.x 更新，但不再以精确版本相等作为唯一条件。运行时必须匹配兼容性档案并通过该档案的能力检查；2.x 需要先建立并验证新的兼容性档案。

模型凭据仅通过凭据引用从 Windows 凭据管理器短暂注入。首次配置由开发者显式选择可执行程序、模型和凭据引用，允许预填发现的程序路径，但不复用未知的全局凭据或配置。

## Consequences

- OpenCode 适配器必须使用真实服务协议，不得保留假设的任务端点作为生产回退。
- 兼容性检查必须给出用户可读的失败原因和恢复建议。
- 密钥不进入界面、IPC、日志、数据库、Diff 或文档。
