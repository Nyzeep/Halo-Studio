# 03 - 确定 P0 发布范围与真实验收场景

**类型：** grilling  
**状态：** resolved  
**Blocked by：** 01 - 定义受管任务会话边界, 02 - 确定真实运行时、兼容性与凭据边界

## Question

首个可用版本应以哪些能力作为发布门槛，真实文件改动在哪个环境中验证，以及 IDE 大型设计是否阻塞该版本？

## Answer

真实验收在开发者明确选择、可安全丢弃的受信任 Git 验收工作区完成。Agent 必须完成一项无害文件改动，开发者再追问一次并进入只读审查。

P0 复用现有配置、任务、轨迹和审查界面，只为真实会话增加最小必要交互。10–13 和 15 号设计保留在统一规格与后续票据中，但不阻塞 P0。

发布证据分为两层：自动化测试覆盖契约和失败边界；开发者通过原生界面完成一次真实会话验收。后者不保存密钥或完整对话。

## Consequences

- 不以 CLI 脚本成功替代原生界面验收。
- 不以模拟 Agent 或假在线状态替代真实 OpenCode。
- 不引入编辑器、资源管理器或命令面板作为 P0 前置依赖。
