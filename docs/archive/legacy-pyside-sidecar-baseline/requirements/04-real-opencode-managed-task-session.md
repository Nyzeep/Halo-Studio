# 04 - 真实 OpenCode 受管任务会话：需求对齐与范围统一

**状态：** 已确认  
**对齐日期：** 2026-07-27  
**适用版本：** 首个具备真实 Agent 应用能力的 Halo Studio 版本  
**依据：** `CONTEXT.md`、`docs/architecture.md`、`docs/ipc-protocol.md`、`docs/module-contracts.md`、`docs/design/10-ide-shell-and-design-language.md` 至 `15-differentiation-features.md`

## 1. 本轮目标

本轮交付的最小产品能力是：本地开发者在 Halo Studio 原生界面中，为验收工作区配置真实 OpenCode 后，启动一个受管任务会话，发送初始任务消息和至少一次追问，处理一次性权限或澄清请求，完成无害文件改动，并在开发者显式结束会话后审查 Diff 与交付证据。

这不是通用自由聊天，也不是由测试替身伪造的“在线”状态。它是围绕一个 Agent 任务的有限、多轮、可审查会话。

## 2. 已确认决策清单

| 编号 | 决策 | 已确认结论 |
| --- | --- | --- |
| D-01 | 对话边界 | 产品提供受管任务会话，不提供无限制自由聊天。 |
| D-02 | 会话轮次 | 初始任务消息后允许同一任务内继续追问或澄清。 |
| D-03 | 会话结束 | Agent 一轮回复后的空闲进入“等待开发者”；仅开发者显式结束会话后进入审查。 |
| D-04 | 首个真实 Agent | OpenCode 是本轮唯一真实端到端发布门槛；Pi 真实运行不阻塞本轮。 |
| D-05 | 验收工作区 | 真实验收在用户明确选择、可安全丢弃的受信任 Git 仓库中进行。 |
| D-06 | 真实任务 | 验收任务须通过真实 Agent 完成无害文件改动，并允许一次追问“改了什么”。 |
| D-07 | 凭据 | 只保存凭据引用；密钥一次性写入 Windows 凭据管理器，界面、IPC、日志和文档均不可见。 |
| D-08 | OpenCode 更新 | 支持从 1.18.5 起的 OpenCode 1.x 更新，但每次启动必须通过兼容性档案定义的能力检查；2.x 须先建立新档案。 |
| D-09 | 首次配置 | 用户显式选择可执行程序、模型和凭据引用，再检查并启动；可预填已发现的程序路径，不自动复用未知全局配置或凭据。 |
| D-10 | 会话呈现 | 任务界面新增活动会话记录，显示用户消息和整理后的 Agent 回复；工具过程仍由运行轨迹呈现。 |
| D-11 | 权限与澄清 | 请求以内嵌卡片呈现；仅支持本次允许、拒绝或填写回答，不支持自动批准和永久规则。 |
| D-12 | 内容安全 | 活动会话记录不展示原始工具日志；文本须脱敏、限长，只在活动会话内保留。 |
| D-13 | 中断 | 应用或 Sidecar 意外退出时，任务标为中断，不自动重连、恢复或重放。 |
| D-14 | 发布范围 | 本轮以真实会话闭环为门槛；IDE 壳层、编辑器、资源管理器、命令面板和差异化功能只纳入后续切片。 |
| D-15 | 测试边界 | 版本化 IPC 是唯一主要测试边界；界面不直接调用 OpenCode。 |
| D-16 | 发布验收 | 自动化协议测试与原生界面下的真实会话验收必须同时通过；真实验收不记录密钥或完整对话。 |

## 3. 统一术语

本轮新增并使用以下术语，定义见 `CONTEXT.md`：

1. 受管任务会话
2. 活动会话记录
3. 等待开发者
4. 验收工作区
5. 凭据引用
6. 兼容性档案
7. 真实会话验收
8. 任务中断

这些术语优先于“聊天”“空闲即完成”“自动恢复”“版本号足够新即可用”等模糊说法。

## 4. P0 端到端验收场景

### 4.1 前置条件

1. 本地开发者已安装 OpenCode 1.x，且版本不低于 1.18.5。
2. 本地开发者已通过 Sidecar CLI 将模型凭据写入 Windows 凭据管理器。
3. 本地开发者已创建或选择一个验收工作区，并在 Halo Studio 中明确授信。
4. 本地开发者在 Halo Studio 中创建 OpenCode 受管启动配置，并通过检查。

### 4.2 通过路径

1. 开发者打开验收工作区并确认其受信任。
2. 开发者选择 OpenCode 启动配置，检查到 1.x 兼容性档案可用并启动受管运行时。
3. 开发者创建任务，要求 Agent 对验收工作区中的无害文本文件执行一处明确改动。
4. Halo Studio 建立真实 OpenCode 会话，活动会话记录显示用户首条消息和 Agent 回复；运行轨迹显示规范化过程。
5. 如 Agent 请求权限或澄清，开发者在会话内一次性处理。
6. Agent 完成一轮回复后，任务状态变为“等待开发者”，不会自动进入审查。
7. 开发者发送至少一次追问，例如“你改了什么？”。
8. 开发者显式选择“结束会话并审查”。
9. Halo Studio 固定任务结束树、生成只读 Diff 与交付证据，并进入审查。
10. 开发者能够看见改动文件、证据摘要和验证结论；接受或拒绝均不触发 Git 提交、推送、回滚或删除。

### 4.3 失败路径

- 版本或能力不符合兼容性档案：运行时不可用，并给出中文原因和恢复建议。
- 凭据引用缺失或凭据存储不可用：失败关闭，不尝试读取明文配置或全局登录状态。
- 权限被拒绝、Agent 失败或会话中断：如实呈现结果，不伪造成功，不自动重放。

## 5. 范围统一

### 5.1 本轮必须交付

- 真实 OpenCode 1.x 的受管启动、认证、健康和兼容性检查。
- 任务级真实 OpenCode 会话、初始消息、追问、等待开发者和显式结束。
- 活动会话记录、运行轨迹、一次性权限或澄清处理、审查入口。
- 任务基线、关联 Diff、脱敏交付证据和现有接受/拒绝边界。
- 自动化契约测试与真实会话验收清单。

### 5.2 明确后置

- Pi 的真实协议适配与真实验收。
- 10 号 IDE 壳层和设计语言。
- 11 号编辑器内核、12 号文件系统与资源管理器、13 号命令面板。
- 15 号差异化功能，包含人工编辑自动归因、任务上下文选择器和审查跳转。
- 多工作区、多任务并发、自由聊天、自动委派、自动重试、自动恢复和永久权限规则。

## 7. 不可突破的红线

1. 不把任何密钥、端口、认证密码或完整原始工具日志写进 UI、IPC、数据库、Diff、文档或错误文案。
2. 不把模拟进程、假在线状态或脚本成功当作真实 Agent 可用。
3. 不让 Halo Studio 代替 Agent 写文件、自动应用补丁、提交 Git、推送远端、创建分支或回滚用户工作区。
4. 不把 Agent 一轮回复或运行时空闲误判为开发者已完成任务。
5. 不对未知 OpenCode 主版本静默放行，不对任何权限创建永久批准规则。
