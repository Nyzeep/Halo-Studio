# 03 - IDE 编辑器嵌入与参考项目对齐

**状态：** 已确认
**对齐日期：** 2026-07-27
**依据：** `01 - Pi/OpenCode 原生工作台的可验证编码交付基础`、`02 - 原生工作台首期任务拆分与依赖关系确认`（两者均已交付并通过验收）

## 问题陈述

首期工作台只提供只读审查，本地开发者在任务过程中仍需切换到外部编辑器修改代码，工作流断裂；
同时首期的 Pi/OpenCode 适配器协议是内部假设协议，尚未与两个受管应用的真实开源实现对齐。

用户提供了五个参考开源项目（`D:\用于参考的开源项目的代码`）：

| 项目 | 参考目的 |
| --- | --- |
| vscode-main | 工作台 UI 布局体系、编辑器组/标签页、命令面板与快速打开、主题令牌 |
| zed-main | 原生编辑器设计（缓冲区/显示层）、极简设计语言、面板与停靠、Agent 面板形态 |
| opencode-dev | OpenCode 真实服务协议（端点、认证、事件流、会话模型），修订适配器 |
| pi-main | Pi 真实 RPC 协议（消息形状、状态、工具事件、取消语义），修订适配器 |
| BitFun-main | 运行时分层、能力/适配器边界、审查生命周期、扩展治理（沿用 01 号记录的借鉴边界） |

## 决定

Halo Studio 由“任务审查工作台”演进为 **内嵌原生编辑器的 IDE 形态开发工作台**。

### 范围内（本轮）

1. **原生编辑器**：QML 原生实现（借鉴 vscode/zed 概念，不借鉴代码），含文件标签页、语法高亮、查找替换、脏状态与保存；**不使用任何 WebView/Monaco**。
2. **IDE 壳层**：Activity Bar / 侧栏（资源管理器 + 现有任务/审查/交接/配置/历史视图归位）/ 编辑器组 / 底部面板 / 状态栏 / 命令面板 + 快速打开。
3. **文件系统契约**：编辑器与资源管理器的文件访问一律经 Sidecar 新增 `fs.*` IPC（工作区路径牢笼、大小上限、二进制检测、信任门禁：未信任工作区不开放 fs 能力）。
4. **真实协议对齐**：以 opencode-dev / pi-main 源码为准修订 halo-runtime 两个适配器与 halo-testkit 假进程（内部适配器协议 v2），保持全部测试绿。
5. **差异化功能**（与“可验证编码交付”正交组合，为本产品独有）：
   - **人工介入自动归因**：运行中任务期间经编辑器保存文件 → Sidecar 自动 `task.mark_manual_edit`，归因如实转 Mixed 并通知用户；
   - **任务上下文选择器**：从资源管理器/编辑器把文件或选区一键加入任务说明；
   - **审查→编辑器跳转**：只读审查中的文件可“在编辑器中打开”并定位行；
   - **基线感知徽章**：资源管理器与编辑器标签标记“任务基线以来已变更”的文件；
   - **归因边栏（gutter）**：编辑器行号侧标记最新交付证据中的 Agent 关联变更行。

### 边界（不变项）

- **交付审查保持只读**：审查视图不变为编辑器；编辑器是独立的人工编辑面，二者可互相跳转但不混合。
- 凭据红线、无 Mock 生产回退、接受/拒绝不动 Git、验证结论三态、单工作区单任务等 01 号记录的全部实施决策继续有效。
- 仍不引入：嵌入式通用终端、WebView、扩展市场、MCP/插件、自动 Git 操作、多工作区。
- BitFun 借鉴边界沿用 01 号记录：借鉴分层/边界/审查生命周期/治理思路，不借鉴 Tauri/WebView 与通用平台定位。

## 文档与实施组织

- 参考分析与模块设计文档统一放在 `docs/design/`，编号规则见该目录 README；
- 每份设计文档对应一个落地开发子代理与代码审查环节；
- IPC 契约的增量（`fs.*` 等）在设计评审后并入 `docs/ipc-protocol.md`（仍为唯一权威），以**追加方式**扩展 v1（新增方法与 capabilities，不改既有消息形状）。
